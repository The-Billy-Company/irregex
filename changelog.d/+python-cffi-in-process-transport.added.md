The Python package now drives the in-process C session ABI (ADR-352 rung 3) over cffi (`gist/_ffi.py` ABI-mode `dlopen` of `libgist.{dylib,so}`), so a persistent `Session` serves eligible queries WARM inside the host process — no subprocess, no Unix socket. Unlike the UDS transport (files/count only), it streams full `Match` records, giving `Session.run` a warm path for the first time; `files`/`count`/`absent` prefer it too, each byte-identical to the cold `gist --json` stream (records, `-l`, `-c`). It is fail-open by construction: `_ffi` returns `None` (→ UDS daemon, then cold subprocess) when the shared library or `cffi` is absent, the ABI version disagrees, the corpus can't open, or the pattern is unsupported (`GIST_STALE`) — so `cffi` stays OPTIONAL and the wheel stays pure-Python and dependency-free (opt out with `GIST_NO_FFI`, override the library with `GIST_LIB`). A handle is cached per process CWD and used only when the caller's `cwd` is that CWD (the one case the rootless in-process walk is byte-identical to a rootless cold run); each `gist_search` runs over its own per-call arena, so overlapping calls can't corrupt one another's scratch. Proven by `tests/test_ffi_parity.py` (FFI ≡ cold: records, files, count incl. multi-hit lines, read-your-writes, deletion reconcile, unsupported→cold, ABI parity).
