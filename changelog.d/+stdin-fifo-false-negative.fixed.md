Piped stdin search (`cmd | gist pattern`) could silently misfire when the producer was slow to write its first byte � a `make` target doing real work, a build tool, a network call. The 200ms poll-based readiness check meant to guard against a pathological never-writing socket also applied to ordinary shell FIFOs, so a slow-starting pipe timed out and fell through to an unrelated directory walk over the current tree instead of searching the piped stream (and the identical per-read poll could truncate a legitimate producer with multi-second gaps between writes). The poll-based hang guard now applies only to sockets � the one fd type it was built for; a FIFO or regular file is trusted immediately (matching ripgrep's own `is_readable_stdin`) and read with a plain blocking read to EOF, since a real pipe's natural stalls have no bearing on when it will actually close.
