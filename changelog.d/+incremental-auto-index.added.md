`gist index --incremental` grafts only the working tree's changed files onto the persisted index (invert the old index → reuse unchanged docs' trigrams, re-read only new/touched ones) instead of rebuilding from scratch — byte-identical to a full build, and 4–6× faster on the Billy corpus (~780 ms vs ~2.5 s over 23k files). `gist index --auto` adds a drift gate (no-op in ms when nothing moved since the freshness anchor) plus a single-flight advisory lock, so it is safe to auto-fire at the end of every operation across the ~10 coworking agents; wired as `make gist-refresh`. `gist status` now reports drift (files touched since the build) alongside the freshness anchor.
